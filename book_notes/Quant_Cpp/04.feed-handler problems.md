# Market-data/feed-handler problems

For example:

* Market data packets contain sequence numbers:

```textile
100
101
103
104
102
105
```

Produce messages in sequence order.

You might maintain:

```cpp
uint64_t expectedSeq;
std::map<uint64_t, Message> pending;
```

But then the real interview starts:

* `std::map` is too slow. What would you use?

* What happens if packet 102 never arrives?

* How do you detect packet loss?

* How do you request recovery?

* How do you avoid dynamic allocation?

This is especially representative of trading infrastructure interviews.
