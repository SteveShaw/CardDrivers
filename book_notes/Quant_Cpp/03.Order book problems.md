# Order book problems

A typical prompt:

* Process these events:

```txt
ADD    orderId price qty side
CANCEL orderId
MODIFY orderId qty
TRADE  orderId qty
```

Support:

```cpp
double bestBid();
double bestAsk();
```

Then the interviewer starts adding requirements:

* Now support 10 million updates/sec.

* Now return total quantity at each price.

* Now preserve price-time priority.

* Now return the first five levels.

* Why are you using `std::map`?

This leads directly into discussions about:

- arrays vs trees
- hash tables
- intrusive lists
- cache locality
- allocation
- price normalization
- integer ticks instead of `double`
- maintaining best bid/ask incrementally
